# 24-hour live soak on Google Axion — 2026-11-11/12

One uninterrupted day of the v0.1.0 release build on live Binance streams, checked every 30 seconds by
`scripts/soak.sh`. Result: **clean**.

- **Host:** Google Cloud `c4a-standard-4` (Axion, Arm Neoverse V2, 4 vCPU, 16 GB), Ubuntu 24.04,
  `europe-southwest1-a` (`ankaa-axion`).
- **Server:** `ankaad serve` as the hardened systemd unit from `deploy/`, release build v0.1.0, live Binance
  trades and 100 ms depth for three symbols, with the write-ahead log, segments, a retention window and two
  continuous queries.
- **Period:** 2026-11-11 14:34 to 2026-11-12 14:34 UTC, 2,875 samples at 30-second intervals. The run
  followed the 3-hour run 7 on the same server process (`docs/benchmarks/` and the site's soak table) and
  a passing `kill -9` crash test before it.
- **Raw data:** [`bench/soak/2026-11-12-gcp-c4a-standard-4-24h.csv`](../../bench/soak/2026-11-12-gcp-c4a-standard-4-24h.csv)
  (every sample: resident and data-tier memory, and every counter the script checks).

## Limits

- One server, one feed (Binance, three symbols), one VM size. A day of three symbols is about 59 million
  rows: this says the engine runs a day without losing or corrupting data and without unbounded memory
  growth at this rate, not how it behaves at a hundred times the rate.
- The build is v0.1.0. Releases after it (0.2.0, 0.3.0) change ingest, storage and query code; they have
  not had a 24-hour run of their own yet.
- No restart during the run; restart and crash behaviour are covered by the crash test before it and by
  the test suite, not by this run.
